01 · The problem

Ordinary RAG runs on autopilot.

Retrieval-Augmented Generation (RAG) gives an LLM an open book: search a document, paste what you find into the prompt, then answer. A good idea, but the standard pipeline follows the same fixed steps every time and never stops to think.

How a conventional RAG pipeline handles every request

Question“How tall is the Eiffel Tower?”
→
1RetrieverSearches the document. Always.
→
2Top K = 3 chunks d3 · How tall is it d9 · A growing tower d11 · Paris cafés
→
3Quality checknone
→
4LLM promptAll 3 chunks pasted in, as-is
→
AnswerNever checked against the chunks
1

It never asks “do I need to look this up?”

A search runs for every request, whether it's a fact question or “write me a poem”. Knowing when to retrieve simply isn't part of the design.

2

It always grabs the same number of chunks

K is a fixed setting, not a judgment. One perfect match or ten, you get exactly K. The same amount every time, whatever the question needs.

3

Nobody checks what came back

The retriever ranks by surface similarity. Nothing asks how relevant or useful a chunk really is, so a weak match looks just as trustworthy as a perfect one.

4

Off-topic chunks go in anyway

Even if every chunk misses the point, all of them are pasted into the prompt. The model tries to use them and gets distracted or misled.

Self-RAG keeps the open book but adds the missing thinking: when to look, whether what it found is any good, and whether its answer matches the source. Below, the same request goes to three systems.

Takeaway

Self-RAG adds two skills to the model: deciding when to retrieve and critiquing its own output. It does both by writing special reflection tokens.

04 · The cast

Three models, one team.

Self-RAG uses three models. Meet each one, then try it yourself.

R

Retriever

Finds the K passages most related to the question.

How: scores every passage against the query, then keeps the top K. The paper scores by meaning (Contriever embeddings). This page scores by keywords (BM25). Details are in “Try the Retriever” below.

C

Critic

A judge that predicts one reflection token for a given input.

Paper: Llama 2-7B trained on GPT-4 labels. Used during training.

G

Generator

The LLM that writes the answer and the reflection tokens, all by itself.

Paper: Llama 2-7B / 13B. This is the model you chat with.

On this page, all three run as small simulations in your browser. They follow the same steps and token rules as the paper, just with simple keyword logic instead of neural networks.

Retriever: find the top-K passages

Type a question. Every passage gets a relevance score, and the top K are handed to the generator.

How does the retriever pick the K passages?

It gives every passage a score for how well it matches the query, sorts them, and keeps the top K. The two methods below differ only in how that score is computed.

In the paper · Dense retrieval (Contriever)

Self-RAG uses an off-the-shelf retriever called Contriever (fine-tuned on the MS MARCO search dataset). It compares meanings, not exact words.

  1. 1
    Encode the passages, once. Before anyone asks anything, every passage is turned into a vector, a list of 768 numbers that captures its meaning. These vectors are stored in an index.
  2. 2
    Encode the query. The same encoder turns the query into a vector. In Self-RAG the query is the question plus the text written so far, so each segment can pull in different passages.
  3. 3
    Score by similarity. Each passage's score is the dot product of its vector with the query vector. Similar meanings point the same way, so they get a high score.
  4. 4
    Keep the top K. Sort by score and take the K best. A vector index (such as FAISS) does this fast, even over millions of passages.
score(q, d) = E(q) · E(d)   →   top-K = the K passages with the highest score

Because it works on meaning, “How high is it?” can match a passage that says “330 metres tall” even with no shared words.

On this page · BM25 keyword scoring

A neural encoder is too heavy to run in this page, so the playground uses BM25, the classic keyword-ranking formula behind many search engines. The pipeline is the same: score every passage, then keep the top K.

  1. 1
    Split into words. Lower-case, remove filler words (the, is, of…), and reduce words to a base form (built → build, taller → tall).
  2. 2
    Rare words count more (IDF). “Eiffel” appears in many passages, so it says little. “Rivets” appears in one, so it's a strong signal.
  3. 3
    Repeats help, up to a point (k₁ = 1.5). A word appearing twice scores more than once, but the gain levels off.
  4. 4
    Long passages are slightly penalised (b = 0.75), so they don't win just by containing more words. Then: sum over the query words, sort, keep the top K.
score(q, d) = Σt ∈ q IDF(t) · tf · (k₁ + 1)tf + k₁ · (1 − b + b · |d| / avgdl)

To get a bit closer to meaning-based search, a few synonyms are added at half weight (e.g. tall → height), and “when / how tall” questions get a small bonus for passages containing dates or numbers.

05 · Put it all together

Watch Self-RAG think.

Self-RAG writes its answer one segment at a time, in a loop. For each segment it may retrieve K passages, write K candidates in parallel, critique them, keep the best one, and start again.

↻
Retrieve is not a one-time switch. The model asks “do I need to look something up?” before every segment, based on the question and what it has written so far. So it can write a first line from memory with Retrieve=No and only start retrieving in the middle of the answer, when it reaches a fact.

    06 · Behind the scenes

    How it learns to do this.

    Training happens in two stages: first a critic learns to judge, then the critic teaches the generator. Press play to walk through it.

    1

    A teacher labels examples

    GPT-4 is asked to judge thousands of examples and write the right reflection token for each one.

    "Is this passage relevant?"→ISREL=Relevant
    2

    Train the critic

    A smaller model (Llama 2-7B) learns to copy GPT-4's judgments. It becomes a cheap, fast judge.

    GPT-4teachesCritic
    3

    Label the training data

    Offline, the retriever and critic go through about 150k question–answer pairs. They insert passages and reflection tokens where needed.

    4

    Train the generator

    The generator learns ordinary next-word prediction on this marked-up text. Reflection tokens are just words it learns to write.

    Generatorlearns to writeISSUP=Fully

    Zoom in on step 2

    Training the critic: what goes in, what comes out

    The critic is one model (Llama 2-7B) that learns all four token types. Each token type is a different question, so each gets different inputs. GPT-4 supplies the correct answer (the target), and the critic is trained to output that same token.

    1. 1Sample a question x and answer y from the training data (plus passages d from the retriever).
    2. 2Ask GPT-4 with a token-specific instruction and a few worked examples. It replies with a label, e.g. [Fully supported].
    3. 3Store the pair (input → target token) in the critic dataset. All four types are mixed together.
    4. 4Fine-tune Llama 2-7B to predict the target token from the input.
    maxC  𝔼((x, y), r) ∼ Dcritic  log pC( r | x, y )   ← ordinary next-token loss, computed only on the target token r

    Takeaway

    When you use Self-RAG, there is no GPT-4 and no separate critic. The generator writes the reflection tokens on its own. This makes it fast, and you can steer it by changing the token weights (like the sliders in the simulator).
